## 开发

> 默认采用idea和vscode开发，配置项涉及插件或格式化，尽量不要更换开发工具

**后端（`backend` 文件夹）**

1. `backend/` 下新建 `application-local.yaml`，写入开发库密码
   ```yaml
   spring:
     datasource:
       password: 开发库密码
   ```
2. 运行 `BackendApplication`，日志出现 `Started BackendApplication` 即成功。

**前端（`frontend` 文件夹）**

```bash
pnpm install
pnpm dev
```

前端配置端口转发，请求 `/api/...` 会自动转发到本机后端 `localhost:8080`。

**代码提交**

1. ***流程***：开分支，提交，pr合并，格式化机器人提交新提交，pull更新，下一次开发，开发完成后提交pr合并

2. ***分支规范***：`类型/描述`，小写、`-` 连接，如 `feat/login`、`fix/kanban-drag`

3. ***提交命名规范***：`类型: 描述`，类型为 `feat` `fix` `docs` `style` `refactor` `chore`，如 `feat: 任务看板拖拽排序`



## 人工部分

### 数据库

- **默认链接服务器上的开发库 `app_dev`**，测试数据库，部署数据库app
- **表结构只能通过脚本改**：脚本放 `backend/src/main/resources/db/migration/`，命名 `V序号__说明.sql`（两个下划线），后端启动时自动执行没跑过的脚本。不要在 Navicat/IDEA 里手动建表改表，否则其他人和线上都不会有这个改动。
- **已合并进 `main` 的脚本不能再改**，改了 Flyway 校验失败、后端启动不了。要改表就新写下一个序号的脚本，比如 `V5__task_add_deadline.sql` 里只写一句 `ALTER TABLE`。
- 例外：表结构稳定前，允许直接改 `V1`，改完清空重建开发库和线上库。
- 写新脚本前在群里说一声自己用哪个序号，避免两个人撞号。
- 共用的开发库里不要执行清空全表、删库之类的语句。

### Git 和自动化

- `main` 受保护，不能直接 push，只能走 PR。
- 提 PR 后**格式化机器人**会自动把 Java 代码格式化，并以 `style: 自动格式化` 提交到你的分支。之后你再 push 会被拒绝，先 `git pull` 再 push（IDEA 弹窗问是否合并时点确定）。
- CI 只检查前后端能不能编译通过，**不检查逻辑对不对，目前也不跑测试**，功能要自己测。
- 部署失败时 GitHub 的 Actions 页面会显示红叉，找管仓库的处理；服务器保留最近 3 个旧版本可回滚。
- 不要提交任何密码；Word、PPT、Excel 已被忽略，放群文件，链接登记在 [`docs/README.md`](docs/README.md)。
